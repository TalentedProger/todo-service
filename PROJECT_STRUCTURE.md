# Структура проекта

Проект намеренно небольшой. В нём нет отдельных слоёв DTO, Repository и Entity: для учебной задачи маршруты и проверка входного JSON находятся в контроллере, а логика работы с БД — в одном сервисе.

## Самые важные файлы

### `src/main/java/ru/study/todo/ApiController.java`

Главная точка входа для HTTP-запросов. Файл:

- объявляет все адреса `/api/v1/users` и `/api/v1/tasks`;
- читает входящий JSON;
- проверяет обязательные поля, email, возраст, статус и ID пользователей;
- задаёт статус `IN_PROGRESS`, если при создании задачи статус не передан;
- вызывает методы `TaskService`;
- возвращает результат в JSON.

Если нужно добавить новый маршрут или изменить формат входящего JSON, начинать следует с этого файла.

### `src/main/java/ru/study/todo/TaskService.java`

Здесь находится основная логика данных:

- модели `Task`, `User` и enum `Status`;
- SQL-запросы на создание, чтение, изменение и удаление записей;
- назначение нескольких пользователей на задачу;
- проверка существования задач и пользователей;
- преобразование строк из БД в JSON-модели.

Методы создания и изменения помечены `@Transactional`: если одна часть операции завершится ошибкой, вся операция отменится.

### `src/main/resources/schema.sql`

Схема базы данных. Создаёт таблицы:

- `users` — пользователи, email уникален;
- `tasks` — задачи и их статусы;
- `task_assignees` — связь «много пользователей на много задач».

База сама создаёт `id` и `created_at`. Внешние ключи удаляют назначения автоматически при удалении задачи или пользователя.

## Остальные Java-файлы

### `src/main/java/ru/study/todo/TodoApplication.java`

Минимальный стартовый класс Spring Boot. Метод `main` запускает HTTP-сервер и приложение. Бизнес-логики здесь нет.

### `src/main/java/ru/study/todo/ApiErrorHandler.java`

Приводит ошибки к единому JSON-виду `{"error":"описание"}`. Обрабатывает неправильный JSON, ошибки проверки, отсутствие записей и конфликт уникального email.

### `src/test/java/ru/study/todo/ApiIntegrationTest.java`

Интеграционный тест всего API. Он запускает приложение с временной БД в памяти и проверяет создание, просмотр, изменение и удаление задач и пользователей, назначения, статус по умолчанию и ответы с ошибками.

## Конфигурационные файлы

### `pom.xml`

Главный файл сборки Maven. В нём указаны Java 21, Spring Boot и зависимости:

- `spring-boot-starter-web` — HTTP и JSON;
- `spring-boot-starter-jdbc` — SQL через `JdbcTemplate` и транзакции;
- `h2` — файловая база данных;
- `spring-boot-starter-test` — средства тестирования.

Все четыре зависимости используются. Spring Boot Maven Plugin собирает запускаемый JAR.

### `src/main/resources/application.properties`

Параметры приложения: адрес файловой БД H2, логин, автоматический запуск `schema.sql`, формат дат в JSON и принудительная кодировка UTF-8 для ответов. Пароль пустой, потому что это локальный учебный проект.

### `.gitignore`

Не даёт добавить в Git результаты сборки, локальную БД, логи и настройки IDE. Эти файлы создаются на конкретном компьютере и не относятся к исходному коду.

### `.mvn/wrapper/maven-wrapper.properties`, `mvnw`, `mvnw.cmd`

Maven Wrapper. Он позволяет собирать проект без отдельной установки Maven:

- `mvnw.cmd` используется в Windows;
- `mvnw` используется в Linux и macOS;
- `maven-wrapper.properties` указывает версию загружаемого Maven.

Эти файлы выглядят объёмными, но нужны для запуска проекта одной командой на разных компьютерах.

### `README.md`

Инструкция по запуску, список маршрутов и готовые примеры отправки JSON.

## Что появляется после запуска

Эти элементы не хранятся в Git:

- `target/` — скомпилированные классы, отчёты тестов и готовый JAR;
- `todo-data.mv.db` — данные созданных пользователей и задач;
- файлы `*.log` — возможные журналы запуска или тестов;
- `.idea/` и `*.iml` — локальные настройки IntelliJ IDEA.

Их можно удалить при очистке проекта. При следующей сборке или запуске нужные элементы появятся снова. Удаление `todo-data.mv.db` удаляет сохранённых пользователей и задачи.
